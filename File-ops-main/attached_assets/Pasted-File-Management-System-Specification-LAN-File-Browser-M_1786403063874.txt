File Management System

# Specification

「LAN内で指定ディレクトリをブラウズするFile Browser」をMVP（Minimum Viable Product）として設計

## File Browser

1. システム概要

	システム名：

	File operat system

目的：

PythonでHTTP Serverを起動し、指定したディレクトリ配下のファイル・フォルダをWebブラウザから閲覧できるようにする。

ドメインは使用せず、LAN内のIPアドレスとポート番号でアクセスする。
'''
Web Browser
     │
     │ HTTP
     ▼
Python / Flask
     │
     ▼
File Browser
     │
     ▼
指定ディレクトリ
(BASE_DIR)
'''
アクセス例：

http://192.168.0.10:8000/

⸻

2. 対象環境

* Linux Server
* Python 3.x
* Flask
* HTML / CSS
* LAN環境
* Windowsでも動作できる構成を考慮

⸻

3. 基本仕様

3.1 Server

Python から Flask Server を起動

Host: 0.0.0.0
Port: 8000
Protocol: HTTP

設定は config.py で管理

例：
'''
BASE_DIR = "/works/data/spec"

11. セキュリティ仕様

ここは重要です

指定した BASE_DIR より上のディレクトリにはアクセスできないようにする

例えば、

BASE_DIR = /works/data/spec

/works/data/spec/projects
↓
はアクセス可能

/works/data
/works
/etc
/root

などにはアクセスできないようにする

特に

../

を利用したPath Traversal攻撃を防止する

例：

/download/../../etc/passwd

のようなリクエストを拒否

これはこのシステムの必須仕様にします

⸻

12. シンボリックリンク

安全性を優先

BASE_DIR外を指しているSymbolic Linkはアクセス禁止

例：

BASE_DIR/
└── secret -> /etc/

のようなリンクがあった場合

/etc/

↑にはアクセスできないようにする

1. 完成系の全体Architecture

最終的には、次のようなLayer構造を想定します
'''
                         Web Browser
                              │
                              │ HTTP / HTTPS
                              ▼
                    ┌──────────────────┐
                    │   Web Frontend   │
                    │ HTML / CSS / JS  │

                             │
                             ▼
                    ┌──────────────────┐
                    │   Flask / API    │
                    │   Application    │
                    └────────┬─────────┘
                             │
          ┌──────────────────┼──────────────────┐
          │                  │                  │
          ▼                  ▼                  ▼
    ┌───────────┐      ┌───────────┐     ┌───────────┐
    │ File API  │      │ Auth API  │     │ Search API│
    └─────┬─────┘      └───────────┘     └─────┬─────┘
          │                                     │
          ▼                                     ▼
    ┌───────────┐                        ┌─────────────┐
    │ File      │                        │ Search      │
    │ Service   │                        │ Service     │
    └─────┬─────┘                        └─────────────┘
          │
          ▼
    ┌───────────────┐

Filesystem
'''

3. ArchitectureのLayer

このシステムでは、主に6つのLayerに分けます
'''
Presentation Layer
        ↓
Routing Layer
        ↓
Service Layer
        ↓
Security Layer
        ↓
Data / Filesystem Layer
        ＋
Infrastructure / Logging
'''
それぞれ役割を固定

⸻

5. Routing Layer

routes/

ここはHTTP Requestを受け取る入口

例：
'''

DELETE /files/<path>
POST /rename
POST /directory/create
GET /search
GET /preview/<path>
POST /login
POST /logout
'''
など

Routeの仕事
'''
Requestを受け取る
        ↓
入力値を確認
        ↓
Serviceを呼ぶ
        ↓
Responseを返す
'''

Route自身がFilesystemを直接操作することは避る

⸻

6. Service Layer

Architectureの中心

 ↓

 ↓
Filesystem
'''
とする

'''

   ↓

   ↓

   ↓

7. Security Layer

security/

ここではFilesystemへのアクセスを管理

※ 特に重要

Path Traversal Protection


例：

../
../../
/etc/passwd

などを使ってBASE_DIRの外へ出ようとするアクセスを拒否！

Architecture
'''
Request
   ↓
Path Security
   ↓
「BASE_DIR内か？」
   ↓
YES → Service
NO  → Reject
'''
とする
